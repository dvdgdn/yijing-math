# Research Ledger

**Full-context material.** Nothing in this directory may be supplied to a minimal-context investigator. For targeted packages, supply only the specific records an assignment needs.

The ledger records what the program has claimed, on what evidence, and with what verification. The specification (fields, statuses, procedures) is [`methods/ledger-conventions.md`](../methods/ledger-conventions.md). This page explains how to find your way around.

Current version: see the first entry of [`CHANGELOG.md`](CHANGELOG.md).

## Read in layers

You do not need to read the whole ledger.

1. **[`summary.md`](summary.md)**: one page on the current state of knowledge, the live disputes, and the largest gaps.
2. **[`INDEX.md`](INDEX.md)**: one row per claim (ID, type, status, domain, title), grouped by kind. Generated by `python3 tools/yj.py index`; do not edit by hand.
3. **Individual records** in [`claims/`](claims/): the authoritative statement, assumptions, provenance, evidence, verification log, scope, objections, and next steps.

Supporting files:

| File | Contents |
|---|---|
| [`definitions.md`](definitions.md) | Definitions and encodings referenced by claims (`DEF-`). Not privileged. |
| [`questions.md`](questions.md) | Precise open questions (`Q-`). |
| [`directions.md`](directions.md) | Broad research directions and their exploration status, including unexplored areas (`DIR-`). |
| [`disputes.md`](disputes.md) | Contradictions and competing explanations, with discriminating tests (`DSP-`). |
| [`verification-backlog.md`](verification-backlog.md) | Claims awaiting verification, in priority order. |
| [`CHANGELOG.md`](CHANGELOG.md) | Ledger versions. |
| [`leak-terms.txt`](leak-terms.txt) | Vocabulary distinctive of current findings, used to check that clean files and minimal packages stay clean. |

## Reading a claim's status correctly

- `reported` means one or more investigators asserted it. **It does not mean proven**, even if the original report says "proof" or "checked by computation".
- `reproduced` means re-derived in an isolated session, but by the same model family or without adversarial audit.
- `verified` means independently checked by a different model family or a qualified human, with the method in the record's verification log.
- `refuted` applies to the formulation stated, never to a whole direction. Read the record's `Not ruled out:` line.
- `value` (worth investigating further) is independent of `status` (how well supported).
- `domain` separates formal mathematics, claims about specific historical sources, historical claims, and interpretations. A `formal` result about an encoding is not a claim about history.
